# Внешние интерфейсы

## WebUI

Назначение:

* ручная загрузка мультимедийного файла пользователем;
* отображение человекочитаемого результата анализа.

Обсуждавшиеся действия:

* пользователь открывает WebUI через браузер;
* пользователь загружает файл;
* WebUI передает файл в модуль приема данных;
* WebUI получает результат анализа;
* WebUI отображает результат пользователю.

Вход:

* мультимедийный файл.

Выход:

* человекочитаемый результат анализа.

Ограничения:

* поддерживаются только изображения, аудио и видео;
* архивы, документы и контейнерные форматы не анализируются автоматически;
* WebUI должен требовать аутентификацию.

Статус:

* обсуждалось на проектном уровне;
* структура экранов WebUI не определена;
* конкретные формы, кнопки и маршруты не проектировались.

---

## API

Назначение:

* автоматизированная передача мультимедийных файлов от внешних систем;
* возврат результата анализа во внешнюю систему в машиночитаемом виде.

Обсуждавшиеся действия:

* внешняя система передает файл через API;
* API проверяет доступ;
* API передает файл в модуль приема данных;
* система выполняет анализ;
* API возвращает JSON-отчет внешней системе.

Вход:

* мультимедийный файл;
* служебные сведения об источнике поступления, если они передаются внешней системой.

Выход:

* JSON-отчет;
* ошибка при недопустимом файле или невозможности обработки.

Ограничения:

* API должен требовать токен;
* может применяться ограничение запросов в минуту;
* может применяться список разрешенных внешних систем;
* конкретные REST endpoint-ы не обсуждались;
* HTTP-методы не обсуждались;
* URL-структура не обсуждалась;
* формат API-ошибок не обсуждался.

Статус:

* наличие API принято как архитектурное решение;
* конкретная спецификация API отсутствует.

# Проверки

## Проверки входного файла

Обсуждавшиеся проверки:

1. Проверка расширения.
2. Проверка MIME-типа.
3. Проверка фактической сигнатуры.
4. Проверка соответствия заявленного и фактического типа.
5. Проверка размера.
6. Проверка возможности безопасного чтения.
7. Расчет SHA-256.

---

## Проверки типа файла

Поддерживаемые типы:

* image;
* audio;
* video.

Неподдерживаемые типы:

* архивы;
* документы;
* контейнерные форматы;
* иные неподдерживаемые файлы.

Поведение:

* неподдерживаемые файлы отклоняются.

---

## Проверки ограничений размера

Обсуждавшиеся проектные ограничения:

* изображение — до 20 МБ;
* аудио — до 50 МБ;
* видео — до 200 МБ.

Статус:

* проектный пример;
* окончательные значения не утверждены.

---

## Проверки параллельной обработки

Обсуждавшиеся проектные ограничения:

* изображения — до 4 параллельных задач;
* аудио — до 2 параллельных задач;
* видео — до 1 параллельной задачи.

Статус:

* проектный пример;
* окончательные значения не утверждены.

---

## Проверки доступа API

Обсуждалось:

* API должен требовать токен;
* может применяться rate limit;
* может применяться список разрешенных внешних систем.

Не обсуждалось:

* формат токена;
* срок действия токена;
* механизм выпуска токена;
* роли API-клиентов;
* формат ошибок авторизации.

---

## Проверки WebUI

Обсуждалось:

* WebUI должен требовать аутентификацию.

Не обсуждалось:

* механизм аутентификации;
* роли пользователей;
* форма входа;
* управление сессиями.

---

## Проверки анализаторов

Обсуждалось:

* анализаторы могут завершаться с ошибкой;
* при сбое отдельного анализатора анализ может продолжаться;
* ошибка анализатора должна быть включена в отчет;
* при необходимости анализ маркируется как неполный.

---

## Проверки риск-оценки

Обсуждалось:

* признаки делятся на слабые, значимые и критичные;
* слабый признак дает небольшой вклад в риск;
* значимый признак заметно повышает риск;
* критичный признак может установить высокий риск;
* наличие critical override должно отражаться в отчете.

---
