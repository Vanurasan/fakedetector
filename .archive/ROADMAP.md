# ROADMAP.md

# 1. Общие принципы разработки

Разработка выполняется поэтапно.

Каждый этап должен завершаться работающим результатом, который можно запустить, проверить и использовать как основу для следующего этапа.

Система не должна сразу пытаться реализовать все анализаторы и все внешние интеграции.

Базовый порядок разработки:

1. каркас системы;
2. прием файлов;
3. проверка файлов;
4. временное хранение;
5. маршрутизация по типу медиа;
6. предварительная обработка;
7. подключение анализаторов;
8. формирование признаков;
9. риск-оценка;
10. отчет;
11. журналирование;
12. удаление временных данных;
13. проверка на тестовых данных;
14. подготовка к дальнейшим интеграциям.

Ограничения:

* не проектировать новые функции;
* не добавлять новые каналы взаимодействия;
* не реализовывать автоматическую распаковку архивов;
* не извлекать мультимедиа из документов;
* не хранить исходные файлы долговременно;
* не формировать бинарный вывод «подделка / не подделка»;
* не привязывать ядро системы жестко к электронной почте.

# 2. Этап 1. Каркас проекта и базовая конфигурация

## Цель

Создать минимальный исполняемый каркас системы, который можно запускать и развивать дальше.

## Что реализуется

* базовая структура проекта;
* подключение конфигурации;
* чтение YAML-конфигурации;
* базовые секции конфигурации:

  * server;
  * access_channels;
  * limits;
  * allowed_formats;
  * validation;
  * temporary_storage;
  * preprocessing;
  * analyzers;
  * risk_assessment;
  * result;
  * error_handling;
  * logging;
  * external_systems;
* подготовка структуры модулей:

  * WebUI;
  * API;
  * прием данных;
  * первичная проверка;
  * маршрутизация;
  * временное хранение;
  * предварительная обработка;
  * анализаторы;
  * формирование признаков;
  * риск-оценка;
  * формирование результата;
  * журналирование;
  * обработка ошибок.

## Что должно быть готово

* проект запускается;
* конфигурация загружается;
* параметры конфигурации доступны модулям;
* есть базовая структура каталогов и модулей;
* система еще не выполняет анализ файлов.

## Что проверяется

* корректная загрузка конфигурации;
* наличие всех базовых секций конфигурации;
* обработка ошибки некорректной конфигурации;
* запуск проекта без анализа файлов.

## Критерий завершения

Система запускается и читает конфигурацию без ошибок.

## Риски

* преждевременное усложнение структуры;
* добавление незафиксированных функций;
* смешивание логики анализа и конфигурации;
* фиксация окончательного технологического стека до его выбора.

# 3. Этап 2. Прием файлов через WebUI и API

## Цель

Реализовать два зафиксированных канала поступления файлов: WebUI и API.

## Что реализуется

* прием файла через WebUI;
* прием файла через API;
* передача файла в единый модуль приема данных;
* создание задачи анализа;
* фиксация источника поступления файла;
* базовая обработка ошибки при отсутствии файла.

## Что должно быть готово

* пользователь может передать файл через WebUI;
* внешняя система может передать файл через API;
* оба канала используют единый внутренний путь обработки;
* создается идентификатор задачи анализа;
* фиксируется канал поступления.

## Что проверяется

* передача файла через WebUI;
* передача файла через API;
* единая обработка файла после поступления;
* создание задачи анализа;
* фиксация источника поступления.

## Критерий завершения

Файл может быть передан в систему через WebUI и API и зарегистрирован как задача анализа.

## Риски

* преждевременное проектирование полной REST API-спецификации;
* дублирование логики приема для WebUI и API;
* жесткая привязка приема файлов к электронной почте;
* отсутствие единого внутреннего механизма обработки файла.

# 4. Этап 3. Первичная проверка входного файла

## Цель

Реализовать проверки, которые должны выполняться до анализа файла.

## Что реализуется

* проверка расширения файла;
* проверка MIME-типа;
* проверка фактической сигнатуры файла;
* проверка соответствия заявленного и фактического типа;
* проверка размера файла;
* проверка возможности безопасного чтения файла;
* расчет SHA-256;
* отклонение неподдерживаемого файла.

## Что должно быть готово

* система принимает только допустимые типы файлов;
* неподдерживаемые файлы отклоняются;
* архивы отклоняются;
* документы отклоняются;
* контейнерные форматы, не входящие в базовую область анализа, отклоняются;
* рассчитывается хэш файла;
* результат проверки передается дальше по цепочке.

## Что проверяется

* допустимое изображение проходит проверку;
* допустимое аудио проходит проверку;
* допустимое видео проходит проверку;
* архив отклоняется;
* документ отклоняется;
* файл с неправильной сигнатурой отклоняется;
* файл сверх допустимого размера отклоняется;
* SHA-256 рассчитывается.

## Критерий завершения

Система корректно принимает допустимые мультимедийные файлы и отклоняет неподдерживаемые файлы до запуска анализа.

## Риски

* доверие только расширению файла;
* отсутствие проверки фактической сигнатуры;
* прием файлов, которые не должны анализироваться;
* слишком ранний запуск анализаторов без валидации.

# 5. Этап 4. Временное хранение и удаление файлов

## Цель

Реализовать временное хранение исходных и промежуточных файлов без долговременного хранения исходников.

## Что реализуется

* размещение файла во временном хранилище;
* привязка временного файла к задаче анализа;
* настройка TTL из конфигурации;
* удаление исходного файла после завершения анализа;
* удаление промежуточных файлов после завершения анализа;
* фиксация факта удаления.

## Что должно быть готово

* исходный файл хранится только на период анализа;
* временные файлы удаляются после обработки;
* промежуточные данные удаляются после обработки;
* в журнал или результат передается статус удаления.

## Что проверяется

* файл появляется во временном хранилище после приема;
* файл доступен модулям обработки;
* файл удаляется после завершения анализа;
* промежуточные файлы удаляются;
* исходный файл не сохраняется долговременно.

## Критерий завершения

Файл проходит полный цикл временного хранения: размещение, использование, удаление.

## Риски

* сохранение исходных файлов после анализа;
* потеря файла до завершения обработки;
* отсутствие фиксации статуса удаления;
* смешивание временного хранилища и журнала результатов.

---

# 6. Этап 5. Маршрутизация по типу медиа

## Цель

Реализовать определение типа медиа и выбор соответствующего пути обработки.

## Что реализуется

* определение типа файла:

  * image;
  * audio;
  * video;
* передача изображения в маршрут обработки изображений;
* передача аудио в маршрут обработки аудио;
* передача видео в маршрут обработки видео;
* отклонение неподдерживаемого типа.

## Что должно быть готово

* система определяет тип медиа;
* задача анализа получает маршрут обработки;
* для каждого поддерживаемого типа есть отдельный путь обработки;
* неподдерживаемый тип не попадает в анализаторы.

## Что проверяется

* изображение маршрутизируется в обработку изображений;
* аудио маршрутизируется в обработку аудио;
* видео маршрутизируется в обработку видео;
* неподдерживаемый файл отклоняется.

## Критерий завершения

Каждый поддерживаемый тип файла направляется в свой маршрут обработки.

## Риски

* неверное определение типа файла;
* маршрутизация по расширению без учета фактической проверки;
* смешивание обработки разных типов медиа;
* отсутствие отдельного маршрута для видео.

---

# 7. Этап 6. Управление задачами и контроль параллельности

## Цель

Реализовать обработку файла как задачи анализа.

## Что реализуется

* создание задачи анализа;
* хранение статуса задачи;
* фиксация времени начала обработки;
* фиксация времени завершения обработки;
* постановка задачи в очередь;
* применение ограничений параллельной обработки из конфигурации.

## Что должно быть готово

* каждая проверка имеет идентификатор analysis_id;
* задача имеет статус;
* задачи могут выполняться через механизм очереди;
* параллельная обработка ограничивается по типу медиа.

## Что проверяется

* задача создается при поступлении файла;
* задача получает статус;
* задача переходит через этапы обработки;
* ограничения параллельности применяются;
* завершенная задача имеет результат.

## Критерий завершения

Файл обрабатывается как управляемая задача с идентификатором, статусом и контролем выполнения.

## Риски

* запуск длительных операций без очереди;
* отсутствие контроля параллельности для видео;
* потеря статуса задачи;
* невозможность связать результат с исходной задачей анализа.

# 8. Этап 7. Предварительная обработка изображений

## Цель

Реализовать подготовку изображений к анализу.

## Что реализуется

* извлечение метаданных изображения;
* нормализация изображения для анализа;
* подготовка изображения для анализаторов;
* передача подготовленных данных в модуль управления анализаторами.

## Что должно быть готово

* изображение после маршрутизации проходит предварительную обработку;
* метаданные извлекаются;
* нормализованная версия изображения доступна анализаторам.

## Что проверяется

* обработка допустимого изображения;
* извлечение метаданных;
* передача подготовленных данных анализаторам;
* корректное завершение обработки изображения без запуска аудио- или видео-маршрутов.

## Критерий завершения

Изображение подготавливается к анализу и передается дальше в едином внутреннем формате обработки.

## Риски

* потеря исходных параметров изображения;
* невозможность передать подготовленные данные анализаторам;
* смешивание предварительной обработки с итоговой риск-оценкой.

* построение спектрограммы;
* подготовка данных для аудиоанализаторов.

## Что должно быть готово

* аудиофайл после маршрутизации проходит предварительную обработку;
* метаданные доступны;
* аудиофрагменты доступны;
* спектрограмма доступна;
* подготовленные данные передаются анализаторам.

## Что проверяется

* обработка допустимого аудиофайла;
* извлечение метаданных;
* создание фрагментов;
* построение спектрограммы;
* передача подготовленных данных аудиоанализаторам.

## Критерий завершения

Аудиофайл подготавливается к анализу и передается дальше в маршрут аудиоанализа.

## Риски

* некорректное чтение аудиоформата;
* избыточное создание промежуточных файлов;

* извлечение технических параметров видео;

* извлечение ключевых кадров;

* подготовка кадров для видео- и визуальных анализаторов;
* подготовка аудиодорожки для аудиоанализа.

## Что должно быть готово

* видеофайл проходит предварительную обработку;
* технические параметры извлечены;
* ключевые кадры извлечены;
* аудиодорожка извлечена;
* подготовленные данные доступны анализаторам.

## Что проверяется

* обработка допустимого видео;

* отсутствие контроля параллельности;

* ошибка извлечения кадров.

# 11. Этап 10. Модуль управления анализаторами

## Цель

Реализовать единый механизм подключения и запуска анализаторов.

## Что реализуется

* чтение списка активных анализаторов из конфигурации;
* запуск анализаторов по типу медиа;
* сбор результатов анализаторов;
* фиксация статуса анализатора;
* фиксация confidence;
* фиксация краткого summary;
* обработка ошибки отдельного анализатора;
* продолжение анализа при сбое отдельного анализатора, если возможно.

## Что должно быть готово

* анализаторы запускаются через единый механизм;
* набор анализаторов зависит от типа медиа;
* отключенные в конфигурации анализаторы не запускаются;
* результаты собираются в общей структуре;
* ошибки анализаторов попадают в результат.

## Что проверяется

* запуск анализаторов изображения;
* запуск анализаторов аудио;
* запуск анализаторов видео;
* отключение анализатора через конфигурацию;
* фиксация ошибки анализатора;
* продолжение анализа при ошибке отдельного анализатора.

## Критерий завершения

Система может запускать активные анализаторы по типу файла и собирать их результаты в едином формате.

## Риски

* жесткая привязка анализаторов к основному процессу;
* невозможность отключить анализатор;
* сбой одного анализатора останавливает весь анализ;
* разные форматы результатов анализаторов.

---

# 12. Этап 11. Подключение анализаторов изображений

## Цель

Реализовать анализ изображений по обсуждавшимся группам методов.

## Что реализуется

* анализ метаданных;
* ELA;
* JPEG/DCT-анализ;
* copy-move detection;
* resampling detection;
* анализ шумовых несоответствий;
* подключение ML-анализаторов изображений, если они выбраны для реализации.

## Что должно быть готово

* изображение проходит через набор анализаторов изображений;
* каждый анализатор возвращает результат в общей структуре;
* результаты передаются в модуль формирования признаков.

## Что проверяется

* выполнение каждого подключенного анализатора;
* корректная фиксация статуса анализатора;
* формирование признаков изображения;
* обработка ошибки отдельного анализатора.

## Критерий завершения

Для изображения формируются результаты анализаторов и признаки, пригодные для риск-оценки.

## Риски

* методы дают неоднозначные признаки;
* отсутствие метаданных может привести к ложной интерпретации;
* отдельные методы не являются доказательством подделки;
* ML-анализаторы могут требовать дополнительной настройки.

---

# 13. Этап 12. Подключение анализаторов аудио

## Цель

* каждый анализатор возвращает результат в общей структуре;
* результаты передаются в модуль формирования признаков.

## Что проверяется

* выполнение каждого подключенного аудиоанализатора;
* формирование аудиопризнаков;
* обработка ошибки анализатора;
* передача признаков в риск-оценку.

## Критерий завершения

Для аудиофайла формируются результаты анализаторов и признаки, пригодные для риск-оценки.

## Риски

* отсутствие финальных весов риск-оценки.

# 26. Этап 25. Фиксация незавершенных вопросов

## Цель

Зафиксировать, что еще не реализовано или требует отдельного проектирования.

## Что реализуется

Новые функции не добавляются.

Формируется перечень нерешенных вопросов:

* окончательный технологический стек;
* схема базы данных;
* модель пользователей;
* модель прав;
* механизм аутентификации WebUI;
* механизм API-токенов;
* формат ошибок API;
* полная спецификация API;
* требования к WebUI;
* окончательный набор анализаторов;
* финальные веса признаков;
* финальные пороги risk scoring;
* финальные датасеты;
* метрики качества;
* почтовый коннектор;
* интеграция с SIEM;
* интеграция с DLP;
* интеграция с SOAR;
* эксплуатационный мониторинг;
* требования к развертыванию.

## Что должно быть готово

* перечень незавершенных вопросов;
* понимание, какие части являются реализованными;
* понимание, какие части остались проектными;
* отсутствие скрытых нерешенных компонентов.

## Что проверяется

* все известные незавершенные вопросы отражены;
* новые функции не добавлены;
* план не противоречит текущим архитектурным решениям.

## Критерий завершения

Сформирован актуальный список оставшихся проектных и технических вопросов.

## Риски

* смешивание реализованных и нереализованных компонентов;
* появление незафиксированных требований;
* неверное представление проектных примеров как окончательных решений.

# 28. Минимальный рабочий результат

Минимальный рабочий результат должен включать:

* прием мультимедийного файла через WebUI;
* прием мультимедийного файла через API;
* первичную проверку файла;
* определение типа медиа;
* временное хранение файла;
* удаление файла после анализа;
* запуск хотя бы базовых анализаторов;
* формирование признаков;
* расчет риск-оценки;
* применение правила критичного признака;
* формирование JSON-отчета;
* отображение человекочитаемого результата;
* журналирование служебных сведений.

Минимальный рабочий результат не должен включать:

* автоматическую распаковку архивов;
* автоматическое извлечение мультимедиа из документов;
* долговременное хранение исходных файлов;
* жесткую привязку ядра к электронной почте;
* бинарный вывод «подделка / не подделка».
