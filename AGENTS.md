# Инструкции для ИИ-агента

## Обязательное чтение

Перед изменением кода необходимо прочитать:

1. `docs/PROJECT.md`
2. `docs/CONTRACTS.md`
3. текущий этап в `docs/ROADMAP.md`

`docs/CHANGELOG.md` читается только при необходимости восстановить историю решений.

## Источники истины

- назначение, архитектура и технологический стек: `docs/PROJECT.md`;
- модели данных и интерфейсы: `docs/CONTRACTS.md`;
- текущий статус и порядок разработки: `docs/ROADMAP.md`;
- история существенных изменений: `docs/CHANGELOG.md`.

## Правила работы

1. Выполнять только текущую задачу из `ROADMAP.md`.
2. Не добавлять незапрошенные функции.
3. Не изменять зафиксированную архитектуру самостоятельно.
4. Не принимать решения со статусом `OPEN` без разрешения владельца.
5. Не считать проектные примеры окончательными контрактами.
6. Перед изменениями кратко описать план.
7. После изменений запустить относящиеся к задаче тесты.
8. Не отмечать этап выполненным без прохождения критериев завершения.
9. Не помещать в Git секреты, исходные медиафайлы, модели и runtime-данные.
10. Не выполнять необратимые команды без явного подтверждения.

## Git

- работать небольшими изменениями;
- не переписывать историю Git;
- не выполнять force push;
- не удалять ветки;
- не выполнять commit без явного запроса;
- перед началом работы проверять `git status`;
- после работы показывать изменённые файлы и результат тестов.

## Документация

- `ROADMAP.md` обновляется после фактического завершения задачи;
- `CHANGELOG.md` обновляется только при существенном изменении поведения,
  архитектуры, контракта или технологического решения;
- архитектурные решения не должны дублироваться в нескольких документах.
